# Contextual Retrieval — 원문 대조 한국어 학습 노트

- 원문: https://outcomeschool.com/blog/how-does-contextual-retrieval-work
- 저자: Amit Shekhar (Outcome School)
- 원문 게시일: 2026-10-06
- 대조 범위: 검색 색인에 공개된 원문 본문·목차·예시를 확인해 핵심 주제와 사례를 대조함. 사이트 직접 페이지 열람은 실패했으므로 원문 전체 문장·그림·코드를 빠짐없이 대조한 완전 검증본은 아님.
- 작성 방식: 저작권을 존중하는 독립적인 한국어 상세 해설이며 원문 전체 번역이 아님.

## 1. 청크 분할의 문맥 손실

문서를 짧은 청크로 분할하면 지시대명사·기간·조직명·문서 출처가 사라질 수 있습니다. 원문은 단독으로 의미가 불완전한 청크가 검색에서 누락되는 문제를 설명합니다.

## 2. 일반 검색의 두 방식

Embedding 기반 검색은 의미적 유사도를 찾고, BM25는 드문 정확한 단어와 용어를 잘 찾습니다. 예를 들어 오류 코드 `TS-999`처럼 정확한 문자열이 중요할 때 키워드 검색의 장점이 큽니다.

## 3. Contextual Retrieval 처리 단계

1. 전체 문서를 청크로 나눕니다.
2. LLM에 원문 문서와 대상 청크를 함께 보여주고 짧은 맥락 설명을 작성하게 합니다.
3. 생성된 설명을 청크 앞에 붙입니다.
4. 확장 청크로 **Contextual Embeddings**와 **Contextual BM25** 인덱스를 만듭니다.
5. 질의 시 두 검색 결과를 통합하고 **reranking**으로 순서를 다듬습니다.

## 4. 원문의 SEC 예시

원문은 SEC 공시의 문맥이 빠진 청크를 사례로 제시합니다. 원래 청크가 '전 분기보다 매출이 3% 증가했다'만 말한다면, 생성한 설명에 'ACME Corp, 2023년 2분기, 이전 분기 매출 3억 1,400만 달러'를 덧붙여 어느 기업·기간의 수치인지 복구합니다. 이 예시는 원문 검색 결과에서 확인한 구체적 설명입니다.

## 5. Prompt Caching과 평가

전체 문서라는 공통 프롬프트 접두부를 청크마다 반복하므로 prompt caching으로 중복 계산을 줄일 수 있습니다. 청크별 설명이 사실을 왜곡하지 않는지 확인하고 Recall@k, MRR, 최종 답변 근거 적합도, 인덱싱 비용을 함께 측정합니다.

## 학습 점검

1. 이 기술의 입력, 처리 단계, 출력은 무엇인가?
2. 원문에서 제시한 예시가 왜 해당 기술의 장점과 한계를 드러내는가?
3. 실제 시스템에서 정확도·비용·안전성을 어떻게 검증할 것인가?

## 출처 검증 메모

원문의 공개 검색 색인에 나타난 핵심 개념·예제와 비교했습니다. 직접 페이지 전체를 안정적으로 열람할 수 없어 이미지·모든 코드 줄·모든 문단까지 1:1 확인했다고 주장하지 않습니다.
