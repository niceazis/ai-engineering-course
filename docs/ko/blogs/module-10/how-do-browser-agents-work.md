# Browser Agents — 원문 대조 한국어 학습 노트

- 원문: https://outcomeschool.com/blog/how-do-browser-agents-work
- 저자: Amit Shekhar (Outcome School)
- 원문 게시일: 2026-10-11
- 대조 범위: 검색 색인에 공개된 원문 본문·목차·예시를 확인해 핵심 주제와 사례를 대조함. 사이트 직접 페이지 열람은 실패했으므로 원문 전체 문장·그림·코드를 빠짐없이 대조한 완전 검증본은 아님.
- 작성 방식: 저작권을 존중하는 독립적인 한국어 상세 해설이며 원문 전체 번역이 아님.

## 1. 정의와 사용 조건

Browser Agent는 웹사이트의 화면 또는 페이지 구조를 관찰하고 클릭·입력·스크롤 등 브라우저 동작을 반복하는 AI 에이전트입니다. 원문은 공식 API가 없거나 API에서 지원하지 않는 작업에 이 방식을 적용한다고 설명합니다.

## 2. 세 구성 요소

**Browser**는 실제 페이지를 표시하고, **Controller**는 Playwright·Puppeteer 같은 도구로 조작하며, **LLM**은 관찰 결과에 따라 다음 행동을 결정합니다. 모델이 브라우저를 직접 제어하는 것이 아니라 컨트롤러가 모델의 요청을 실행합니다.

## 3. 화면 인식 두 방식

스크린샷은 시각적 배치를 이해하지만 이미지 토큰 비용과 좌표 오차가 있습니다. DOM·접근성 트리는 버튼·텍스트 필드 등 요소를 구조적으로 보여주고 정밀하게 선택할 수 있지만 캔버스 기반 UI에는 취약합니다. 혼합 방식도 가능합니다.

## 4. Observe–Think–Act

1. Observe: 현재 페이지 스크린샷 또는 번호가 붙은 요소 목록을 얻습니다.
2. Think: 사용자 목표와 이전 행동을 고려해 한 번의 다음 행동을 선택합니다.
3. Act: 컨트롤러가 클릭·입력·스크롤 등을 수행합니다.
4. 페이지가 바뀌므로 매 행동 뒤 새로 관찰합니다. 요소 번호는 화면마다 달라질 수 있습니다.

## 5. 원문의 서점 예제

원문은 **Atomic Habits 페이퍼백을 장바구니에 넣기**를 7라운드로 설명합니다. 서점 열기 → 검색어 입력 → 검색 버튼 → 결과 선택 → 페이퍼백 선택 → 장바구니 추가 → 완료 메시지 확인입니다. 실제 구매·결제는 수행하지 않는 예제입니다.

## 6. 코드 구조와 중단 조건

원문 Python 예시는 Playwright로 브라우저를 열고 `list_clickable_elements`, `page.screenshot`, `llm_decide`, `perform` 같은 함수를 반복하며 최대 20단계에서 중단합니다. 일부 함수는 개념 설명용 헬퍼로, 그대로 실행 가능한 완성 프로그램이 아닙니다.

## 7. 보안과 실패 처리

팝업, 느린 로딩, 로그인, CAPTCHA, 동적 UI를 처리해야 합니다. 페이지 속 숨겨진 지시문은 **prompt injection**일 수 있으므로 신뢰된 사용자 명령으로 취급하지 않습니다. 결제·삭제·메시지 발송처럼 영향 큰 행동에는 사용자 확인을 둡니다. API가 있으면 일반적으로 API를 우선합니다.

## 학습 점검

1. 이 기술의 입력, 처리 단계, 출력은 무엇인가?
2. 원문에서 제시한 예시가 왜 해당 기술의 장점과 한계를 드러내는가?
3. 실제 시스템에서 정확도·비용·안전성을 어떻게 검증할 것인가?

## 출처 검증 메모

원문의 공개 검색 색인에 나타난 핵심 개념·예제와 비교했습니다. 직접 페이지 전체를 안정적으로 열람할 수 없어 이미지·모든 코드 줄·모든 문단까지 1:1 확인했다고 주장하지 않습니다.
