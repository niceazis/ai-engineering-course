## 1. 생성형 AI를 한 문장으로 이해하기

생성형 AI(Generative AI)는 학습 데이터의 패턴을 바탕으로 **새로운 텍스트, 이미지, 오디오, 비디오, 코드 같은 결과물을 만들어 내는 AI**입니다.

Outcome School의 공식 소개는 기존 AI를 “분류하거나 결정하는 AI”, 생성형 AI를 “새로운 것을 만드는 AI”로 대비합니다. 예를 들어 기존 시스템이 이메일을 스팸/정상으로 분류한다면, 생성형 모델은 이메일 본문 자체를 새로 작성할 수 있습니다.

핵심은 단순히 저장된 답을 꺼내는 것이 아니라, 학습한 통계적 패턴을 사용해 현재 입력에 맞는 새로운 출력을 구성한다는 점입니다.

## 2. Generative + AI라는 이름의 의미

- **AI**: 데이터에서 패턴을 학습해 예측이나 의사결정을 수행하는 모델과 시스템을 뜻합니다.
- **Generative**: 주어진 입력을 바탕으로 이전에 그대로 존재하지 않았던 출력을 생성한다는 뜻입니다.

따라서 생성형 AI는 “예측”과 “생성”이 별개의 과정이라는 뜻이 아닙니다. 특히 언어 모델에서는 **다음 토큰을 예측하는 작은 동작을 반복한 결과가 긴 문장 생성**으로 나타납니다.

Outcome School 공식 소개도 이 지점을 강조합니다. 긴 답변이 한 번에 작성되는 것처럼 보여도 내부적으로는 다음 단어/토큰 후보를 계속 예측하고 이어 붙이는 과정으로 이해할 수 있습니다.

## 3. 기존 AI와 생성형 AI의 차이

| 관점 | 전통적인 판별/예측 AI | 생성형 AI |
| --- | --- | --- |
| 대표 질문 | “이 입력은 어느 범주인가?” | “이 입력에 맞는 새 결과를 만들어라.” |
| 출력 | 클래스, 점수, 확률, 예측값 | 텍스트, 이미지, 코드, 오디오 등 |
| 예 | 스팸 탐지, 신용 위험 예측 | 문서 작성, 이미지 생성, 코드 생성 |
| 공통점 | 데이터에서 패턴을 학습함 | 데이터에서 패턴을 학습함 |

둘을 완전히 다른 기술로 보면 안 됩니다. 생성형 모델도 내부적으로는 확률을 계산하고 예측합니다. 차이는 그 예측을 **연속적으로 사용해 구조화된 새 콘텐츠를 만든다**는 데 있습니다.

## 4. 생성형 AI는 어떻게 학습하는가

공식 레슨 개요의 흐름은 다음과 같습니다.

1. 많은 예시 데이터를 본다.
2. 데이터 안의 반복되는 패턴과 관계를 학습한다.
3. 입력이 들어오면 학습한 패턴을 이용해 가능한 다음 출력을 계산한다.
4. 그 과정을 반복해 완성된 결과를 만든다.

언어 모델을 예로 들면, 학습 중에는 문맥 다음에 어떤 토큰이 등장하는지를 반복해서 맞힙니다. 이 과정에서 문법, 표현, 사실의 연관성, 코드 구조 같은 다양한 통계적 패턴이 파라미터에 녹아듭니다.

중요한 점은 모델이 원문 문장을 데이터베이스처럼 그대로 저장해 두었다가 단순 검색하는 것으로 이해하면 안 된다는 것입니다. 생성 시점에는 현재 문맥과 모델 파라미터를 바탕으로 다음 토큰의 확률 분포를 계산합니다.

## 5. “새로운 결과”가 만들어지는 과정

언어 생성은 다음과 같이 볼 수 있습니다.

    사용자 입력
        ↓
    입력을 토큰으로 변환
        ↓
    현재 문맥에서 다음 토큰 확률 계산
        ↓
    토큰 하나 선택
        ↓
    선택한 토큰을 문맥 뒤에 추가
        ↓
    다시 다음 토큰 예측
        ↓
    종료 조건까지 반복

예를 들어 시작 문맥이 “AI is”라면 모델은 다음 후보들의 확률을 계산하고 하나를 선택합니다. 새 토큰이 추가되면 문맥이 바뀌므로 다음 확률 분포도 다시 계산됩니다.

이 연속 생성 구조는 다음 레슨인 Autoregressive Model과 직접 연결됩니다.

## 6. 무엇을 생성할 수 있는가

생성형 AI의 출력은 텍스트에 한정되지 않습니다.

- 텍스트: 질문 답변, 요약, 번역, 문서 작성
- 코드: 함수 생성, 리팩터링, 테스트 작성
- 이미지: 설명문을 바탕으로 이미지 생성
- 오디오: 음성 합성, 음악 생성
- 비디오: 프롬프트 기반 영상 생성
- 멀티모달 결과: 텍스트와 이미지·음성 등을 함께 처리

모달리티는 달라도 “학습한 분포에서 조건에 맞는 새 샘플을 만든다”는 큰 틀은 같습니다.

## 7. 생성형 AI에서 ‘모델’이란 무엇인가

모델은 입력을 받아 출력의 확률이나 표현을 계산하는 학습된 함수라고 볼 수 있습니다.

언어 모델이라면 매우 단순화해 다음과 같이 표현할 수 있습니다.

    P(next_token | tokens_so_far)

즉, “지금까지의 토큰이 주어졌을 때 다음 토큰이 무엇일 가능성이 높은가?”를 계산합니다.

사용자가 보는 챗봇 제품은 모델만으로 구성되지 않습니다. 실제 서비스에는 시스템 프롬프트, 도구 호출, 검색, 안전 정책, 메모리, UI 같은 요소가 추가됩니다. 따라서 “ChatGPT 같은 제품”과 “기반 언어 모델”을 같은 것으로 취급하지 않는 것이 좋습니다.

## 8. 전체 동작 흐름

학습과 사용을 분리해 보면 이해가 쉽습니다.

### 학습

    대규모 데이터
      → 토큰화/전처리
      → 모델 예측
      → 정답과 오차 계산
      → 파라미터 업데이트
      → 반복

### 추론

    사용자 입력
      → 토큰화
      → 모델 실행
      → 다음 토큰 확률
      → 디코딩/샘플링
      → 토큰 반복 생성
      → 최종 결과

생성형 AI를 이해할 때 “학습할 때 지식을 파라미터에 반영하는 단계”와 “이미 학습된 모델로 결과를 생성하는 단계”를 구분해야 합니다.

## 9. 일상적인 활용

생성형 AI는 초안 작성과 반복 작업에서 특히 강합니다.

- 긴 자료 요약
- 이메일·보고서 초안
- 질문 답변
- 코드 작성 및 설명
- 아이디어 발산
- 번역과 표현 변환
- 이미지·디자인 시안 제작

다만 실제 업무에서는 생성 결과를 그대로 정답으로 간주하지 않고 **검증 가능한 절차**와 함께 사용하는 것이 중요합니다.

## 10. 한계

생성형 모델의 출력은 확률적입니다. 자연스럽게 보인다는 사실이 곧 사실성을 보장하지 않습니다.

주요 한계는 다음과 같습니다.

- 사실과 다른 내용을 그럴듯하게 만들 수 있음
- 학습 데이터의 편향이 출력에 반영될 수 있음
- 동일한 입력에도 설정에 따라 다른 결과가 나올 수 있음
- 최신 정보나 사내 정보처럼 학습에 없던 정보는 별도 검색/RAG가 필요할 수 있음
- 긴 문맥에서도 중요한 정보가 묻히거나 놓칠 수 있음

따라서 중요한 작업에서는 “생성”과 “검증”을 분리해야 합니다.

## 11. 다음 레슨과 연결

생성형 AI 전체 그림을 잡았다면 다음 질문으로 이어집니다.

1. 왜 언어 모델은 한 번에 전체 답을 만들지 않고 토큰을 하나씩 생성하는가?
2. 전체 문장의 확률은 어떻게 각 토큰 확률로 분해되는가?
3. 미래 토큰을 보지 못하게 하는 causal masking은 왜 필요한가?
4. 반복 계산을 줄이기 위해 KV Cache는 무엇을 저장하는가?

이 질문들이 바로 Autoregressive Model, Attention, KV Cache로 이어집니다.

## 핵심 정리

- 생성형 AI는 새로운 콘텐츠를 만드는 AI입니다.
- 언어 모델의 생성은 다음 토큰 예측을 반복한 결과입니다.
- 학습 단계와 추론 단계를 구분해야 합니다.
- 생성형 모델은 텍스트뿐 아니라 이미지·오디오·코드·비디오에도 적용됩니다.
- 출력이 자연스럽다고 사실이 보장되는 것은 아니므로 검증 계층이 필요합니다.
