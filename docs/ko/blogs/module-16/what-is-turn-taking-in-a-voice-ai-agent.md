# 음성 AI 에이전트의 턴테이킹: 엔드포인팅과 끼어들기

> 원문: https://outcomeschool.com/blog/what-is-turn-taking-in-a-voice-ai-agent  
> 원저자: Amit Shekhar (Outcome School), 2026-10-19  
> 검증: 원문 URL 직접 열람은 실패했으나 검색 엔진의 **해당 원문 페이지 색인 본문·표·FAQ** 및 공식 upstream 모듈 16.9 소개를 확인했습니다. 아래는 독립적으로 구성한 한국어 학습 노트입니다. 시간·확률 수치는 설명용 예시이며 제품의 권장 설정값이 아닙니다.

## 1. 턴테이킹의 두 가지 과제

사람과 대화할 때는 언제 상대방이 말을 끝냈는지 예측해야 합니다. 음성 에이전트는 특히 두 문제를 해결해야 합니다.

1. **End-of-turn detection(endpointing):** 사용자가 발화를 완료했는지 판단하고 답변 생성을 시작합니다.
2. **Interruption handling(barge-in):** 에이전트가 말하는 중 사용자가 발언권을 되찾으려고 할 때 재생을 멈추고 듣습니다.

원문에 소개된 대화 연구에서는 10개 언어의 발화 교대 간격이 흔히 **0~200ms**에 몰린다고 설명합니다. 사람들은 문장의 마지막 음절을 듣기 전에 말의 끝을 예측합니다. 이는 사용자 경험의 맥락을 설명하는 수치이지 에이전트에 설정할 절대 SLA가 아닙니다.

## 2. 왜 침묵만으로 충분하지 않은가?

사용자가 1초 침묵했다고 가정하겠습니다. 질문을 끝냈을 수도 있고, 숫자를 읽으려다 잠시 멈췄을 수도 있으며, 다음 문장을 생각하는 중일 수도 있습니다. 같은 길이의 무음이어도 의도는 다릅니다.

- 너무 빨리 응답하면 미완성 요구를 확정합니다.
- 너무 오래 기다리면 통화가 끊어진 듯한 공백을 만듭니다.
- 의미, 억양, 앞선 발화, 침묵의 위치를 결합해야 합니다.

## 3. 구성 요소와 역할

```text
마이크 -> 오디오 프레임 -> VAD -> STT/ASR -> 턴 검출
                                           |
                                     발화 완료 판정
                                           v
                                     LLM + 도구
                                           |
                                      TTS -> 스피커
                        (재생 중에도 새 입력을 감시)
```

- **VAD(Voice Activity Detection):** 프레임이 사람 음성인지 판단하며 단어의 의미를 읽지 못합니다. 원문은 20ms 오디오 조각을 예시로 듭니다.
- **STT/ASR:** 오디오에서 텍스트를 얻습니다. 실시간 중간 결과는 수정될 수 있습니다.
- **턴 검출:** 문장이 완결되었는지 판단하고 사용자의 발화를 언제 확정할지 결정합니다.
- **TTS:** 생성된 답변을 음성으로 바꾸며, 끼어들기를 지원하려면 재생 중 취소할 수 있어야 합니다.

## 4. 접근법 A: 고정 무음 타임아웃

VAD가 일정 시간 연속 무음을 감지하면 발화가 종료됐다고 선언합니다. 원문은 **700ms** 타이머를 설명에 사용합니다.

| 임계값 예시 | 장점 | 위험 |
| --- | --- | --- |
| 300ms | 응답 시작이 빠름 | 생각 중 잠깐 쉬는 사용자를 차단 |
| 700ms | 중간 수준의 대기 | 문장 완결성을 구별하지 못함 |
| 1500ms | 발화 중단 오판 감소 | 완결된 질문에도 응답이 느려짐 |

고정값은 간단하고 계산량이 작지만 언어와 화자의 차이를 반영하기 어렵습니다. 수치는 원문에 나온 비교용 값이며 실제 서비스의 최적값을 의미하지 않습니다.

## 5. 접근법 B: 의미 기반 턴 검출

STT 텍스트와 상황을 입력으로 문장이 끝났을 가능성을 평가합니다. 음향 정보나 억양을 함께 처리하는 검출기도 있습니다.

| 인식된 발화 | 설명용 완료 점수 | 행동 |
| --- | ---: | --- |
| "영업시간이 어떻게 되나요?" | 0.95 | 짧게 대기 후 응답 |
| "네 명 자리 예약을..." | 0.05 | 나머지 발화를 기다림 |
| "번호는 4512 8890..." | 0.20 | 숫자가 이어질 가능성 고려 |
| "네, 이상입니다." | 0.97 | 짧게 대기 후 응답 |

이 점수는 원문의 개념 설명을 위한 가상 값이며 교정된 모델의 실측 확률이 아닙니다. 실무에서는 **VAD로 침묵 포착 → 의미 모델로 완결성 확인 → 완결성이 높으면 짧은 대기, 낮으면 긴 대기**를 결합할 수 있습니다.

## 6. 중단과 맞장구는 다릅니다

에이전트가 설명하는 중 고객이 "아니요, 화요일로 바꿔 주세요"라고 하면 재생을 중단해야 합니다. 하지만 "네", "음", "맞아요"는 듣고 있다는 표시인 **backchannel**일 수 있습니다. 기침, 주변 대화와 스피커 에코는 진짜 발언권 요청이 아닙니다.

| 감지된 입력 | 의미 | 동작 |
| --- | --- | --- |
| "네", "음" | 맞장구 | 계속 재생 |
| 기침·문 닫는 소리 | 배경 소음 | 계속 재생 |
| "잠깐, 그게 아닙니다" | 정정·중단 | 음성 출력 중단 |
| "그만" | 짧은 중단 요청 | 지체 없이 중단 |

단순히 일정 시간 음성이 지속되어야 중단하는 방법은 짧은 "그만"을 놓칠 수 있습니다. 단어의 의도와 신뢰도를 함께 평가해야 합니다.

## 7. 재생 취소가 필요한 이유

- **AEC(Acoustic Echo Cancellation):** 스피커에서 나온 에이전트 자신의 목소리가 마이크로 돌아오는 것을 억제합니다.
- **재생 버퍼 비우기:** TTS 생성 취소만으로는 재생 대기 중인 음성이 남을 수 있습니다.
- **부분 발화 보존:** 중단을 감지한 순간의 첫 단어를 버리지 않습니다.
- **대화 이력 정합성:** LLM이 생성한 다섯 문장 중 실제로 두 문장만 들려줬다면 사용자에게 전달된 두 문장만 대화 기록에 반영합니다.

## 8. Half-duplex와 full-duplex

원문은 턴 중심의 STT→LLM→TTS 구조를 half-duplex 에이전트로, 오디오를 동시에 입력·출력할 수 있는 모델을 full-duplex 구조로 대비하며 Kyutai의 Moshi를 예로 듭니다. 전자는 컴포넌트별 제어·디버깅이 쉽고, 후자는 동시 대화와 짧은 추임새를 자연스럽게 처리할 가능성이 있습니다.

**주의:** 대화 정책이 교대식이라는 뜻과 오디오 전송이 단방향이라는 뜻은 다릅니다. 턴 중심 에이전트에서도 끼어들기 감지를 위해 마이크 수신과 TTS 재생을 동시에 유지합니다.

## 9. 실습

1. 같은 800ms 침묵을 완결된 질문과 미완성 문장 뒤에 삽입하여 모델 반응을 비교합니다.
2. 단순 고정 timeout과 의미 기반 timeout에서 조기 응답률·평균 대기 시간을 측정합니다.
3. 재생 도중 "네"와 "그만"을 구별하는지 확인합니다.
4. 에코 제거가 꺼진 경우 에이전트가 자기 음성에 반응하는지 확인합니다.
5. 중단된 답변의 **실제 재생 범위**와 다음 턴의 문맥이 일치하는지 테스트합니다.
